# Forma — Formik + Yup и React Hook Form

Две независимые формы профиля: основная на Formik + Yup и дополнительная на React Hook Form со встроенной валидацией.

Домашнее задание: `hw-47-r10.pdf`. Базовая лекция: `#10. Forms. Validation. Formik, Yup, React-hook-form.pdf`.

## Возможности

Основная форма: имя, email, пароль, подтверждение пароля и согласие на обработку тестовых данных в текущей вкладке. Дополнительная форма содержит те же поля, а также телефон и дату рождения. Ошибки отображаются рядом с полями; есть подсказки к паролю, показать/скрыть пароль, очистка и результат успешной проверки.

Переключение вкладок не уничтожает черновик другой формы. Состояния, ошибки и результаты двух форм независимы. Доступна клавиатурная навигация по вкладкам стрелками, Home и End. После успешной отправки пароль и подтверждение очищаются и не входят в отображаемый результат.

**Стек:** React 19, Vite 8, Formik 2, Yup 1, React Hook Form 7, CSS.

## Запуск в VS Code

Установите Node.js **24** (рекомендуется; минимальная версия проекта — 22.12) и откройте папку этого репозитория через File → Open Folder. Либо из терминала в общей папке архива:

```bash
cd hw-47-forms
code .
npm install
npm run dev -- --open
```

Откроется `http://127.0.0.1:5173/`. `code .` — необязательная команда: при отсутствии VS Code в PATH папку можно открыть вручную. Команды npm выполняются во встроенном Terminal → New Terminal, **из папки с package.json**. Сервер останавливается Ctrl+C.

Зависимости уже перечислены в package.json; повторно выполнять `npm create vite` и устанавливать каждую библиотеку отдельно не нужно. Файл `.nvmrc` содержит `24`; при установленном совместимом менеджере версий можно использовать `nvm install` / `nvm use`. Менеджер версий не обязателен.

Первое подключение к npm создаст `package-lock.json`. Его следует включить в репозиторий. Затем используйте `npm ci` для повторяемой установки. В архив не включены node_modules и dist.

## Компоненты и правила

`src/components/FormikForm.jsx` использует `useFormik` и `validationSchema` из `src/validation/profileSchema.js`. `src/components/HookForm.jsx` использует `useForm`, `register`, `handleSubmit`, `formState.errors` и встроенные `validate`-правила из `src/lib/validation.js` — Yup к этой форме не подключён.

| Поле | Правило |
|---|---|
| Имя | Обязательно, после trim от 2 до 50 символов |
| Email | Обязательно, до 254 символов, проверка формата адреса |
| Пароль | Обязательно, 8–72 символа, хотя бы одна буква и одна цифра, без пробелов |
| Подтверждение | Обязательно, точное совпадение с текущим паролем |
| Согласие | Должно быть отмечено |
| Телефон (RHF) | `+`, ненулевой код страны, всего 7–15 цифр; пробелы, `(`, `)` и `-` разрешены как оформление |
| Дата рождения (RHF) | Реальная календарная дата, от 1900-01-01 до сегодняшнего дня |

В Formik дополнительные требования к паролю и подтверждение описаны Yup-схемой. В RHF изменение пароля повторно проверяет подтверждение через `deps`. Проверка даты учитывает несуществующие даты, високосные годы и будущие значения. Проверка email и телефона является проверкой формата, а не подтверждением существования адреса или владения номером.

`Field.jsx` связывает label, input, подсказку и ошибку через `id`, `htmlFor`, `aria-describedby` и `aria-invalid`. В React 19 `ref` передаётся как prop и доходит до настоящего input, который регистрирует RHF. `Consent.jsx`, `PasswordChecklist.jsx`, `ProfileResult.jsx` разделяют ответственность.

### Обработка результата

`publicProfile` создаёт объект по белому списку: имя, нормализованный email и, для RHF, телефон/дата рождения. Пароль, подтверждение, согласие и посторонние поля в результат не попадают. Результат сохраняется **только в локальном React-state**; это один из вариантов, прямо разрешённых PDF. Нет запроса регистрации, настоящей учётной записи, постоянного хранения, логирования паролей или синхронизации.

Для проверки используйте вымышленные данные, например `Анна`, `anna@example.com`, `Example123`, `+380 67 123 45 67`, `2000-02-29`. Перезагрузка страницы очищает обе формы и результаты. Результаты сохраняются при переключении вкладок до перезагрузки.

### Соответствие PDF и обновление API

Основное задание и дополнительное выполнены в одном проекте: две формы, минимум три поля, сообщения об ошибках, обработка результата, дополнительные телефон/дата рождения, независимые состояния. Основная и дополнительная формы не являются двумя дополнительными репозиториями.

В лекции пример RHF на странице 30 использует старый синтаксис `ref={register(...)}` и `errors` непосредственно в объекте `useForm()`. В проекте применён актуальный API RHF 7: `{...register('field', rules)}` и `formState.errors`, согласно официальному README/API. Смысл задания сохранён; устаревший синтаксис не скопирован.

Базовый путь берётся из метаданных Pages, поэтому любое допустимое имя репозитория не требует ручной правки конфигурации.
